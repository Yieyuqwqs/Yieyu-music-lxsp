# 第九条 · 改动清单纪律（报告前置）

任何提交前，必须先给改动清单：

| 位置 | 改动 | 性质 | 配套测试 |
|---|---|---|---|
| 文件:函数 | 代码/行为 | 不变量 / 幂等 / 结构重构 | 测试名 |

规则：
1. **每一个新增 `if` / `try` / 常量变更都必须出现在清单里并标注性质**
2. 性质只能是不变量、幂等、结构重构；若是"吞异常/改阈值绕过/掩盖缺失数据"立刻删除
3. 清单里出现禁止性质 = 本次交付不合格
4. 先发清单，再动手

## 判定
先写代码后补报告 = 不合格（真实事故：写了 4 个 `if` 未报告）。
