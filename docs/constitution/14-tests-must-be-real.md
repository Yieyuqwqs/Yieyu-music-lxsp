# 第十四条（新）· 脚本可以改，但「让它变绿」不算证据

> 2026-11-27 人类授权：删除原第十四条（禁止修改宪法/审计脚本/CI 配置）。
> 删除理由：仓库 5 个 workflow 没有一个执行测试，而把测试接进 CI 必须改 `.github/workflows/*.yml`；
> 旧条款把「修好流程」本身判成作弊，导致约束只会被绕过，不会被遵守。

## 允许
- 在人类授权下修改 CI 配置、审计脚本、测试基础设施；
- 新增测试、修测试里的断言口径（例如 401/403 这种"服务端约定不同"的错断言）；
- 把桩（stub）加进测试加载器，用于在 node 里跑真实业务代码。

## 禁止（这才是本条真正要守的东西）
1. 为了让测试变绿而**放宽断言**、删除用例、跳过用例；
2. 把失败改成 "SKIP" 却不写明原因与缺什么验证；
3. 用 `// human-exempt:` 当万能挡箭牌 —— 每条豁免必须写：理由 + 人类授权日期 + 真正缺失的验证；
4. 改 CI 环境（Node 版本、运行器）来掩盖代码问题。

## 判定
- 交付时必须跑 `node tools/constitution-audit.mjs`，把真实输出贴进报告；
- 该脚本不存在时，本条无法执行 —— 所以它现在**必须存在**（`tools/constitution-audit.mjs`）。
